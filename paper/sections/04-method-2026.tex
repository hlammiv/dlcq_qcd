\section{The numerical method}
\label{sec:method}

The 1990 program worked in three steps~\cite{Hornbostel:1988fb}.  It
generated all color-singlet partitions of $K$, removed overcomplete
directions by diagonalizing the inner-product matrix, and diagonalized the
Hamiltonian in the surviving basis.  Free and interacting parts were stored
separately, so a change of coupling is a rescaling rather than a rebuild.
Nothing in that architecture needed changing.  What changed is what it
runs on.

We run two implementations against each other.  The first is the original
Fortran, kept unmodified as a historical reference.  The second is an
open-source Python port whose matrix builds are verified bit-identical to
their own independent reference path (Appendix~\ref{app:data}).  The two
solvers agree at the level of the arithmetic, not the plot.  One defect of
the original era was found along the way: both codebases silently capped
the color-contraction tables, which corrupted matrix elements above certain
basis sizes with no warning.  Both paths now raise.

Three observations take the reachable resolution from $2K = 16$--$24$ to
$2K \simeq 100$ on a laptop-class machine.  First, the inner-product matrix
is exactly block diagonal in parton configuration, verified by brute-force
color enumeration.  Orthonormalization therefore never needs the dense
$n^2$ object that was the binding memory constraint.  Second, the
Hamiltonian in the weeded basis is sparse and gets sparser with $K$, so an
iterative eigensolver pays off once the norm is blocked.  Third, a
blockwise basis projects the free part to an exact diagonal, which removes
the last dense intermediate.  None of this approximates the physics: the
sparse path must reproduce the dense reference to solver precision, and the
standard-Hamiltonian path remains bit-identical to what the code has always
produced.

Resolution is bounded above on purpose.  At $2K = 100$ the solver
reproduces its recorded reference values in seconds.  Past it, the color
path returns spurious negative eigenvalues below an otherwise intact
spectrum; the released code raises instead of returning them.  Wrong-parity
requests also raise.  Mesons need even $2K$ and baryons need
$2K \equiv N \bmod 2$; the failure mode this closes is an empty spectrum
returned in a tenth of a second, which reads as a fast successful run.

The 1990 paper noted its largest runs took ``one to three minutes of CPU on
an IBM 3081.''  The corresponding statement here: the full table of
extrapolated masses, some eight hundred solves, rebuilds from nothing in
about six minutes on one idle workstation.  The binding constraint is no
longer time or memory.  It is the endpoint physics of Sec.~\ref{sec:budget}.
